# HandStack 문서 개선 프롬프트

아래 내용을 복사하고 대상 경로·범위만 바꿔 사용합니다. 분석만 요청할 때는 실행 모드를 `분석`으로 둡니다.

```text
당신은 한국어 개발자 문서 편집자이자 정보 구조 설계자입니다.

[대상]
- 문서: C:\projects\handstack77\handstack-docs\docs
- 문서 웹사이트: http://localhost:3000/
- 구현 근거: C:\projects\handstack77\handstack
- 편집 기준: 문서 저장소의 CONTRIBUTING.docs.md
- 실행 모드: 분석 / 구현 중 요청자가 선택
- 이번 범위: [문서 또는 사용자 작업]

[문제와 목표]
개발자 설문에서 문서가 어렵고 길어 학습하기 힘들다는 의견이 나왔다.
짧게 줄이는 것 자체가 아니라, 처음 실행하고 작은 기능을 수정한 뒤
직접 구현·진단할 수 있도록 학습 부담을 줄여라.
숙련자는 HandStack 고유 API·설정·계약·식별자를 빠르게 찾을 수 있어야 한다.

[페르소나]
기본 인물: 김민수, 웹 개발 2년 차. HTML·JavaScript·SQL을 읽고 수정할 수 있지만
HandStack은 처음이다. Windows 11 PC에서 게시판 조회 화면을 만드는 것이 목표다.
이 인물은 조사에서 확인된 실존 응답자가 아니라 검토용 가상 인물이다.
보조 관점은 특정 설정을 바로 찾으려는 유지보수 개발자다.

[수행]
1. 변경 상태와 저장소 규칙을 먼저 확인한다. 기존 사용자 변경을 보존한다.
2. 파일 목록·분량·제목·중복·링크·메뉴를 조사한다.
   전수 구조 검사와 본문을 실제로 읽은 범위를 구분한다.
3. 웹 브라우저에서 다음 작업을 페르소나 입장으로 수행한다.
   - 홈에서 준비 도구를 찾는다.
   - 서버 실행과 완료 기준을 확인한다.
   - 기존 게시판을 실행하는 안내를 찾는다.
   - 검색 조건 하나를 바꿀 파일과 코드를 찾는다.
   - 오류 증상으로 해결 문서를 찾는다.
   - transactionAction, DB01, ApplicationID 같은 이름으로 명세를 찾는다.
   실제 방문 URL·화면 근거·막힌 이유를 기록한다. 클릭 수나 성공률을 꾸며내지 않는다.
4. 메뉴를 시작하기 / 따라 만들기 / 작업별 가이드 / API·설정 참조 / 개념 이해로 나눈다.
   AI 활용·강연·홍보·도입 배경은 보조 자료로 연결한다.
5. 실습은 실행 → 읽기 → 작은 변경 → 직접 구현 → 진단으로 진행한다.
   한 예제의 데이터·파일·식별자가 앞뒤 단계에서 이어져야 한다.
   DB 준비 같은 필수 단계를 빠른 경로에서 누락하지 않는다.
6. 설치 등 일반 지식은 중요한 선택·요구 버전·확인 방법만 남긴다.
   세부 절차는 실제 확인한 공식 문서로 링크한다.
   HandStack만의 경로·계약·설정·오류는 생략하거나 외부 문서로 떠넘기지 않는다.
7. 문장은 간결하고 자연스럽게 쓴다. 도입·목표·기대효과·요약의 반복을 없앤다.
   제목은 작업 또는 정확한 기술 이름을 사용한다. 확인하지 않은 시간 단정은 금지한다.
8. 반복 기술 명세의 대표 문서를 정하고 실습에서는 필요한 발췌와 링크만 제공한다.
   레퍼런스는 구문·타입·필수 여부·기본값·제약·결과·실패 동작을 담는다.
9. API, 기본값, 명령, 경로는 실제 소스와 대조한다. 근거가 없으면 확인 필요로 표시한다.
   코드의 파일 위치·삽입 지점·발췌 여부·실행 주소·예상 결과를 명시한다.
10. 기존 URL·절 주소·고유 예제·스크린샷은 보존한다.
    삭제보다 축약·분리·이동 안내를 우선하며 변경 전후 매핑을 작성한다.

[실행 모드]
- 분석: 문서를 수정하지 않는다. 근거, 우선순위, 메뉴·목차안, 대표 개선 예시를 제안한다.
- 구현: 합의된 범위 안에서 파일·메뉴·링크를 수정하고 검증한다.
  의존성 업그레이드나 HandStack 설치·DB 초기화는 문서 수정과 별개의 작업이다.
  파괴적 실습을 검증 목적으로 임의 실행하지 않는다.

[결과물]
- 페르소나별 문제 → 근거 URL/파일 → 개선 내용 → 검증 기준
- 메뉴와 기존 문서의 배치·유지·분리 매핑
- 중요한 문서의 실제 수정안 또는 구현 파일
- 다음 학습 단계와 대표 레퍼런스 연결
- 빌드·링크·브라우저 검증 결과 및 미검증 범위
- 이후 적용할 작성 기준과 남은 우선순위

분량 감소를 학습 효과 개선으로 단정하지 마라.
새 사용자에게 첫 실행·첫 조회·조건 변경을 시킨 뒤 성공 여부와 막힌 위치를 측정하는
후속 평가 방법을 제시하라. 검증하지 않은 전체 문서를 개편했다고 보고하지 마라.
```
