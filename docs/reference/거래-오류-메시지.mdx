# 거래 오류 메시지

거래가 실패했을 때 응답의 `ExceptionText`나 브라우저 콘솔에 나온 문구로 원인을 찾습니다. 증상에서 시작하는 진단 순서는 [증상별 문제 해결](/docs/guides/문제-해결), 계약 항목은 [거래 계약 명세](/docs/reference/거래-계약-명세), 모듈 설정은 [transact 모듈](/docs/reference/api/modules/transact)을 보세요.

HTTP 상태가 200이어도 응답 본문에 `ExceptionText`가 있을 수 있습니다. 문구 앞부분의 `'ApplicationID|ProjectID|TransactionID|ServiceID'` 값을 계약과 대조하는 것이 가장 빠릅니다.

문구는 `transact` 모듈 소스(`TransactionController`, `TransactClient`)와 화면 로더(`syn.js`) 기준입니다. 서버 `SecurityHardening.SanitizeErrorText`가 `true`이면 클라이언트에는 `요청을 처리할 수 없습니다. 참조 ID: {GlobalID}`만 돌아가고 원본 문구는 서버 로그(`Information`)에 남습니다. 이 경우 응답에서 아래 문구를 검색할 수 없으므로 참조 ID(`GlobalID`)로 서버 로그를 찾으세요.

## 서버: 요청 검증

| 문구 | 발생 조건 | 확인할 설정 |
|---|---|---|
| `요청 정보 확인 필요` | 요청 본문을 읽지 못함 | 요청 전문 형식 |
| `요청 한도 초과` | `SecurityHardening.RateLimit`가 한도를 넘고 `Mode`가 `Enforce`. 다른 모드는 로그만 남깁니다 | `SecurityHardening.RateLimit` |
| `요청 경로 수 한도 초과(… > …)`, `입력 데이터맵 수 한도 초과(… > …)` | 요청의 `Routes` 수나 입력 데이터맵 수가 `MaxRoutes`, `MaxDataMapSetCount`를 넘음 (각 기본값 0은 무제한) | `SecurityHardening` |
| `잘못된 요청` | `IsValidationRequest`가 `true`(기본 `false`)일 때, `BypassGlobalIDTransactions`에 없는 거래가 `System.Routes`가 비었거나 `GlobalID`가 분산 캐시에 시딩되어 있지 않음. 시딩된 `GlobalID`는 한 번 쓰면 지워집니다 | `IsValidationRequest`, `BypassGlobalIDTransactions` |
| `요청 만료` | 같은 검증 중 요청 시각(`RequestTick`)이 180초를 넘음 | 클라이언트·서버 시각 |
| `중복 요청` | `IsValidationGlobalID`가 `true`이고 같은 `GlobalID`를 이미 처리함 | `IsValidationGlobalID` |
| `잘못된 입력 전문` | `Action`, `Kind`, `System`, `Transaction`, `PayLoad`, `Interface` 중 하나가 비어 있음 | 요청 전문 형식 |
| `입력 데이터 맵 정보 확인 필요` | 입력 데이터맵을 역직렬화하지 못함 | 요청 `PayLoad` |
| `데이터 포맷 '…' 확인 필요` | `dataFormat`이 `J`·`T`가 아님 (비어 있으면 `J`) | 요청 `dataFormat` |
| `'…' 환경정보 구분코드 허용 안됨` | 요청 `environment`가 `AvailableEnvironment`에 없거나 목록이 비어 있음 | `AvailableEnvironment` |
| `입력 전문 '…' 환경정보 구분코드 확인 필요` | 요청 `environment`가 비어 있음 | 요청 `environment` |
| `애플리케이션 ID: '…', 프로젝트 ID: … 요청 가능 거래 매핑 정보 확인 필요` | `AllowRequestTransactions`에 `*`나 해당 애플리케이션·프로젝트가 없음 | `AllowRequestTransactions` |
| `제한된 거래 요청입니다.` | 테넌트 앱 경로(Referer)에서 온 호출인데 서비스의 `CommandType`이 `AllowTenantTransactionCommands`에 없음. 코드 기본값은 빈 목록이고 배포 `module.json`은 `["D","G"]`입니다 | `AllowTenantTransactionCommands` |

## 서버: 계약 조회

| 문구 | 발생 조건 | 확인할 것 |
|---|---|---|
| `ProgramID '…', BusinessID '…', TransactionID '…' 거래 Transaction 입력 전문 확인 필요` | 서버에 해당 거래 계약이 없음 | 파일 위치와 이름, ApplicationID·ProjectID·TransactionID, 배포·`refresh` |
| `FunctionID '…' 거래 매핑 정보 확인 필요` | 계약에 `ServiceID`가 없음 | 오타·대소문자 |
| `FunctionID '…' 거래 매핑 중복 정보 확인 필요` | 같은 `ServiceID`가 둘 이상 | 계약의 `ServiceID` 중복 |
| `ScreenID '…' 요청 가능화면 거래 매핑 정보 확인 필요` | 호출 화면이 서비스의 `AccessScreenID`(생략 시 자기 `TransactionID`)에 없음 | 다른 화면·팝업·공용 거래가 호출하면 `AccessScreenID`에 화면 ID 추가 |
| `거래 라우팅 경로 확인 필요` | 서비스의 `RoutingCommandUri`가 `http`를 포함하지 않음 | `RoutingCommandUri`, [라우팅 설정](/docs/reference/api/modules/transact) |
| `ReturnType 확인 필요` | 지원하지 않는 `ReturnType` | 서비스의 `ReturnType` |
| `PSH 동시 처리 한도 초과` | `SecurityHardening.MaxConcurrentPushTasks` 초과 (`PSH` 거래) | `MaxConcurrentPushTasks` |

## 서버: 인증과 권한

판정 방식은 [거래 계약 명세의 접근 제어](/docs/reference/거래-계약-명세#접근-제어)를 보세요.

| 문구 | 발생 조건 | 확인할 것 |
|---|---|---|
| `인증 자격 증명 확인 필요` | `IsPermissionRoles`가 `true`인데 공개 경로나 사용자 역할 정규식이 요청 경로 `/{App}/{Project}/{Transaction}`와 맞지 않음 | `PermissionRoles` 정규식, 로그인 사용자 역할 |
| `앱 사용자 역할 또는 정책 권한 확인 필요` | 쿠키 사용자의 `Roles`·`Policys`·`TransactionTokens` 검사가 모두 실패 | 계약의 `Roles`, `Policys`, 사용자 역할 |
| `BearerToken 역할 또는 정책 권한 확인 필요` | BearerToken 사용자의 같은 검사가 모두 실패 | 위와 같고 토큰의 `Policy.Claims` |
| `'…' 애플리케이션, '…' 프로젝트 또는 … 역할 권한 확인 필요` | `UseApiAuthorize`가 `true`인 서비스에서 역할 검사 실패 | `UseApiAuthorize`, 역할 |
| `TransactionToken 확인 필요` | `AuthorizeMethod`가 `TransactionTokenOnly`인데 토큰이 맞지 않음 | `TransactionTokens` |
| `…: BearerToken 정보 확인 필요.`, `BearerToken 기본 무결성 확인 필요`, `BearerToken 사용자 무결성 확인 필요`, `BearerToken 정보 무결성 확인 필요`, `…: BearerToken 정보가 훼손되거나 확인 할 수 없습니다.` | 토큰 형식·서명·사용자 ID 검증 실패 | 토큰 발급·전달 경로, 다시 로그인 |
| `SystemID: … 확인 필요` | 요청 시스템 ID가 `ModuleConfiguration.SystemID`와 다름 | `SystemID` |
| `거래 액세스 토큰 IP 유효성 오류`, `거래 액세스 토큰 유효성 오류`, `거래 액세스 토큰 유효기간 만료` | 거래 액세스 토큰의 IP·해시·만료 검증 실패 | 토큰 발급 시점의 클라이언트 IP, 유효기간 |
| `개발 테스트 계정 자동 로그인 클레임이 비정상 요청에 포함되어 있습니다.` | `IsEnabledDevAutoSignIn`이 꺼졌거나 `RunningEnvironment`가 `D`가 아닌데 개발 자동 로그인 claim이 있음 | 개발 자동 로그인 설정, 위조 의심 |
| `인증 또는 권한 확인 오류 - …` | 인증 처리 중 예외 | 서버 로그 |

## 클라이언트: 화면 로더 경고

`syn.js`의 `syn.$l.eventLog`가 브라우저 콘솔에 남깁니다. 서버로 가기 전에 멈추거나 응답을 화면에 반영하지 못할 때 나옵니다.

| 문구 | 수준 | 원인 |
|---|---|---|
| `functionID "…"에 대한 거래 설정을 찾을 수 없습니다.` | Warning | 화면 `transaction`에 해당 키가 없음. 키 오타, 객체 이름이 파일명과 다름 |
| `"…" Row List Input Mapping 확인 필요`, `"…" Row Control Input Mapping 확인 필요`, `"…" Row Input Mapping 확인 필요`, `"…" List Input Mapping 확인 필요` | Warning | 입력 `dataFieldID`의 대상 컨트롤(`syn-datafield`, `belongID`)이 없거나 중복. 그리드 열 `belongID` 확인 |
| `afterTransaction('validators continue false', …)` | (훅 호출) | 그리드 열 `validators`(`require`, `unique`) 실패. `callback`이 아니라 `afterTransaction`의 `error`로 전달됩니다 |
| `"…" Form Output Mapping 확인 필요`, `"…" Grid Output Mapping 확인 필요`, `"…" Chart Output Mapping 확인 필요` | Error | 출력 `dataFieldID`의 대상 컨트롤이나 `syn_data`가 없음 |
| `"…" 기능의 거래 응답 정의와 데이터 갯수가 다릅니다` | Error | 서버가 돌려준 결과 집합 수가 화면 `outputs` 수와 다름. `Exception` 집합과 `DisposeResult` 포함 여부 확인 |
| `"…" 거래 중복 또는 존재여부 확인 필요` | Error | 같은 `functionID`가 중복되었거나 거래 정보를 만들지 못함 |

응답을 화면에 반영하는 단계의 오류는 `result.errorText`에 담겨 `callback`으로 전달됩니다. 입력 매핑 경고는 콘솔에만 남으므로 Network 탭에서 요청이 실제로 나갔는지 함께 확인하세요. 화면 객체 구조와 매핑 규칙은 [거래 호출](/docs/reference/거래-호출)을 보세요.
