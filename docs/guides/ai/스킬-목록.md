# 스킬 목록과 설치

HandStack 프로젝트를 개발하는 에이전트가 쓰는 **Claude Code·Codex CLI 공용 스킬 14개**입니다. 특정 프로젝트에 종속되지 않으며, 각 스킬은 작업 대상 저장소의 `AGENTS.md`/`CLAUDE.md`/`DESIGN.md`를 먼저 읽고 그 규약을 우선합니다. 스킬은 판단 절차와 점검 순서를 담고, 구문과 설정값은 이 사이트의 문서를 인용합니다.

## 스킬 14개

| 스킬 | 언제 쓰나 |
|---|---|
| `handstack-feature-delivery` | 새 업무 기능·화면 구현, 필드·조회 조건·버튼 추가. 연결표 작성 → 구현 순서 → 영향 범위·검토 체크리스트 |
| `handstack-screen-development` | 화면 HTML/JS, `syn-datafield`·`belongID` 바인딩, AUIGrid, 팝업, 셸 버튼 |
| `handstack-transaction-contracts` | `.txn` 거래와 `.dbc` SQL 계약, `Flag` 저장, 다중 `seq`, 계층형·순차 거래 |
| `handstack-function-contracts` | `.fnc` 서버 함수(C#·Node.js·Python), `Exception` 출력, featureSQL |
| `handstack-external-contracts` | command(`.bas`)·graphclient(`.cyp`)·repository(`.rpo`)와 파일 첨부 |
| `handstack-prompt-contracts` | prompter(`.pmt`) 프롬프트, Jev·Ollama 판단 계약, LLM 설정 경계 |
| `handstack-workflow-contracts` | `CommandType W` 서버 워크플로: 단계 매핑, 검증, 일회성 워크플로 |
| `handstack-rules-and-verification` | 업무 규칙 정리, 결정표, 동시성·재시도, 경계값 테스트 도출, 결함 기록 |
| `handstack-module-development` | 모듈 구조, `module.json`, `menus.json`, C# 모듈 코드, 빌드·배포 경로, 새 모듈 템플릿 |
| `handstack-cicd-pipeline` | 빌드·검증·패키징·배포 파이프라인 단계, 배포 방식, 릴리즈 기록·롤백 |
| `handstack-host-operations` | ack·rdy·agent·deploy·forbes 호스트, `handstack` CLI, 설정 계층, 관리 API |
| `handstack-source-trace` | 화면 → 거래 → SQL·함수 호출 경로 추적, 변경 영향 분석 |
| `handstack-troubleshooting` | 증상·오류 메시지에서 실패 계층과 원인 확정 |
| `handstack-ide-development` | IDE 왕복 편집 보존, IDE 호스트 저장소 개발 |

각 스킬의 원문은 저장소의 [agent-skills/skills](https://github.com/handstack77/handstack-docs/tree/master/agent-skills/skills) 아래 `<스킬 이름>/SKILL.md`입니다.

## 설치

[handstack-developer-skills.zip](pathname:///agent-skills/handstack-developer-skills.zip)을 받아 압축을 풀고, 그 폴더에서 PowerShell로 실행합니다. 저장소를 받아 `agent-skills` 폴더에서 실행해도 같습니다.

```powershell
# 변경될 경로만 미리 확인
.\Install-Skills.ps1 -Scope User -WhatIf

# 모든 프로젝트에서 사용: Claude Code(~/.claude/skills), Codex CLI(~/.agents/skills)
.\Install-Skills.ps1 -Scope User

# 특정 저장소에서만 사용: <프로젝트>/.claude/skills, <프로젝트>/.agents/skills
.\Install-Skills.ps1 -Scope Project -ProjectRoot C:\path\to\project

# 도구·스킬 선택
.\Install-Skills.ps1 -Tool ClaudeCode -Scope User -Skill handstack-source-trace,handstack-screen-development

# 이전 버전을 백업하고 교체 / 더 이상 쓰지 않는 이전 스킬 이름을 백업 폴더로 이동
.\Install-Skills.ps1 -Scope User -Update
.\Install-Skills.ps1 -Scope User -Update -RetireSkill <이전-스킬-이름>
```

- 같은 이름의 스킬이 다른 내용이면 **아무것도 덮어쓰지 않고 중단**합니다. `-Update`를 주면 `.claude/skills-backup/<시각>/`, `.agents/skills-backup/<시각>/`에 백업한 뒤 교체합니다.
- 개인(User)과 프로젝트(Project) 범위에 중복 설치하면 같은 이름이 여러 위치에서 발견되므로 한쪽만 쓰세요.
- 설치기는 MCP 연결·키·권한 설정을 바꾸지 않습니다. 스킬이 인용하는 문서를 에이전트가 직접 읽게 하려면 [문서 MCP 서버를 등록](/docs/guides/에이전트에-문서-연결하기)하세요.

설치한 뒤 새 세션에서 `/스킬이름`(Claude Code) 또는 `$스킬이름`(Codex CLI)을 입력했을 때 스킬이 보이는지 확인합니다.

## 호출 예시

Claude Code(`/스킬이름`):

```text
/handstack-feature-delivery 게시글 목록 조회 + 등록/수정/삭제 화면을 BOD 프로젝트에 추가해 줘.
/handstack-source-trace BOD010의 저장 버튼이 어떤 SQL까지 가는지 추적해 줘.
/handstack-troubleshooting 조회하면 "거래 응답 정의와 데이터 갯수가 다릅니다"가 떠.
/handstack-transaction-contracts 부모-자식 그리드를 한 번에 저장하는 MD01을 만들어 줘.
```

Codex CLI(`$스킬이름`):

```text
$handstack-screen-development BOD010에 상태 조회 조건을 추가하고 기존 거래에 맞춰 연결해 줘.
$handstack-function-contracts 외부 API를 호출해 결과를 반환하는 서버 함수를 .fnc에 구현해 줘.
$handstack-module-development 새 화면을 메뉴에 등록하고 버튼 기능을 연결해 줘.
```

자동 선택은 각 스킬의 `description`으로 이루어지지만 명시 호출이 가장 확실합니다. 프로젝트 지침과 사용자의 요청이 스킬의 일반 규칙보다 우선합니다. 상황별 요청 문장은 [프롬프트 쿡북](/docs/guides/ai/프롬프트-쿡북), 스킬이 쓰는 점검 스크립트는 [점검 도구](/docs/guides/ai/점검-도구)를 보세요.
