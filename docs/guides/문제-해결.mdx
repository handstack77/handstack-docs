# 실행·화면·거래 문제 해결

오류가 난 단계부터 확인하세요. HTTP 상태가 200이어도 거래 응답에 오류가 있을 수 있으므로 응답 본문과 서버 로그를 함께 봅니다.

## 서버에 접속되지 않음

1. `ack` 터미널이 열려 있고 기동 오류 없이 대기 중인지 확인합니다.
2. 실행 로그의 포트와 브라우저 주소를 비교합니다. 기본 주소는 `http://localhost:8421`입니다.
3. 다른 프로그램이 같은 포트를 사용하는지 확인합니다. 포트를 바꿨다면 화면의 서버 연결 설정도 함께 맞춥니다.

관리 화면이 열리면 [게시판 첫 조회](/docs/tutorial/첫-조회)로 돌아갑니다. 명령을 찾지 못하거나 런타임 오류가 나면 [도구 확인](/docs/startup/install/필수-프로그램-설치하기#설치-완료-기준)을 먼저 수행하세요.

## 화면이 비어 있거나 리소스가 404임

`BOD010.html`을 파일 탐색기에서 직접 열지 말고 `http://localhost:8421/view/BOD/BOD010.html`로 접속하세요.

브라우저 개발자 도구의 Network에서 HTML, `syn.loader.js`와 화면 JS 요청을 확인합니다. 404인 파일은 [계약 파일 경로](/docs/reference/식별자와-파일-경로)와 비교하세요. 설정을 변경했다면 [wwwroot 모듈](/docs/reference/api/modules/wwwroot)의 계약 위치도 확인합니다.

수정 후 새로고침했을 때 화면과 필요한 리소스가 모두 로드되면 다시 조회합니다.

## no such table: Board {#board-table}

실제로 연결된 SQLite 데이터베이스에 `Board` 테이블이 없는 상태입니다. 배포본에 따라 첫 조회에서 빈 테이블을 자동 생성할 수도 있으므로 모든 환경에서 이 오류가 나는 것은 아닙니다.

### 처음 실행하는 실습용 예제

:::warning 초기화하면 기존 게시글이 삭제됩니다

**게시판 Board 테이블 초기화**는 `ZD01` 계약으로 기존 `Board` 데이터와 ID 순번을 지우고 예제 데이터를 넣습니다. 기존 데이터가 있는 환경이나 운영 DB에서 실행하지 마세요.

:::

1. 별도로 준비한 실습 환경인지 확인합니다.
2. 예제 화면의 **게시판 Board 테이블 초기화** 버튼을 누르고 확인 메시지를 읽습니다.
3. 초기화 완료 후 **조회**를 누릅니다. 게시글이 표시되면 해결된 것입니다.

### 기존 데이터가 있는 환경

초기화하지 말고 `BOD010.xml`의 `datasource`와 서버에 등록된 데이터 원본이 의도한 DB 파일을 가리키는지 확인하세요. 배포본에 포함된 파일과 현재 편집한 계약이 같은지도 비교합니다.

연결을 바로잡은 뒤 조회를 다시 수행합니다. 설정 항목은 [dbclient 레퍼런스](/docs/reference/api/modules/dbclient)를 참고하세요.

## 오류는 없는데 목록이 비어 있음

- 제목을 비우고 분류를 ‘전체’로 바꿉니다. 날짜 범위에 데이터의 작성일이 포함되는지 확인하세요.
- 응답 본문에 데이터가 있는지 확인합니다. 없다면 SQL 조건과 연결 DB를 확인합니다.
- 응답에는 데이터가 있는데 화면만 비었다면 HTML의 `syn-datafield`와 JS의 `outputs[].dataFieldID`, 계약의 출력 형식과 순서를 비교합니다.

이름을 맞춘 뒤 다시 조회해 표시 여부를 확인하세요. [거래 호출의 연결 규칙](/docs/reference/거래-호출#입출력-연결)을 참고합니다.

## 거래 설정이나 계약을 찾지 못함

화면 JS의 거래 이름, JSON의 `ServiceID`, XML의 `statement id`를 대조하세요. `HDS / BOD / BOD010 / LD01`이 각각 어느 파일과 항목인지 [식별자 레퍼런스](/docs/reference/식별자와-파일-경로)에서 확인할 수 있습니다.

파일을 고친 뒤에도 예전 계약이 실행되면 배포본의 계약 감시·캐시 설정을 확인하세요. 서버 관리 API의 인증이나 공개 거래 범위를 오류 회피 목적으로 풀지 마세요.

재현 정보를 정리하려면 [결함 재현과 원인 분석](/docs/tutorial/테스트와-디버깅/결함-재현과-원인분석)을 확인하세요.
