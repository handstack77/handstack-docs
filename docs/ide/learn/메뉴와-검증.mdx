# 업무 메뉴 연결하고 검증하기

화면 단독 실행을 확인했다면 실제 사용자가 들어오는 업무 메뉴에서도 같은 결과가 나오는지 확인합니다.

## 1. 메뉴에서 화면 열기

1. **도구 > 유틸리티 > 메뉴 정보 관리**를 엽니다.
2. 현재 프로젝트의 `wwwroot/idelab/menus.json`을 선택합니다.
3. 기존 `LAB010` 화면 메뉴를 선택하고 이름, 표시 여부, `DirectoryID`, `ItemID`를 확인합니다. 새 메뉴가 필요할 때만 추가합니다.
4. 저장한 뒤 **웹 브라우저로 열기**로 업무 셸의 메뉴·탭·기능 버튼을 확인합니다.

예시 연결은 `DirectoryID=LAB`, `ItemID=LAB010`입니다. 프로젝트에 `main.html`이 있으면 화면을 업무 셸 탭으로 엽니다. 메뉴 파일 규칙은 [메뉴와 파일 경로](../reference/파일과-저장-규칙.mdx#메뉴-연결)에서 확인하세요.

## 2. 화면과 HTTP 요청 구분해서 시험

**도구 > 개발 도구 > 거래 클라이언트**에서는 실제 모듈 서버 주소·본문·헤더를 확인하며 요청을 보낼 수 있습니다. 처음 요청을 만들 때는 **Payload 작성**을 이용하고, 계약 편집기의 성공 요청과 비교하세요.

| 시험 | 남길 증거 |
|---|---|
| 메뉴로 열어 정상 조회 | 화면 경로, 입력값, 결과 건수 |
| 없는 검색값으로 조회 | 빈 목록과 오류 없는 응답 |
| 시험 요청의 기능 ID만 없는 값으로 변경 | HTTP 상태와 거래 오류 메시지 |

실패 시험은 실습 서버의 복사한 요청에서만 수행합니다. 저장·삭제 계약을 무작정 실행하지 말고, 시험 후 원래 요청으로 되돌려 정상 조회를 다시 확인하세요. 기능 버튼이 보인다는 사실만으로 해당 기능이 구현된 것은 아닙니다.

## 3. 실패를 추적하기

로그 DB가 준비되었다면 **업무 > 프로젝트 관리 > 모니터링 > 거래 이력정보**에서 시각·거래·기능 ID로 좁히고 `GlobalID`로 서버 로그를 연결합니다. 로그 수집이 설정되지 않았다면 하단 **서버·콘솔·출력**에서 최초 오류를 확인합니다.

소스 수준 조사가 필요할 때만 [ack 디버깅 조건](../reference/문제-해결.mdx#중단점이-잡히지-않음)을 확인하세요. 화면 캡처나 요청 전문을 공유하기 전 인증 헤더·연결 문자열·개인정보를 제거합니다.

## 직접 확인

다른 사람이 반복할 수 있도록 `환경 → 입력 → 기대 결과 → 실제 결과 → 증거 위치`를 기록하세요. 정상 조회와 의도한 실패를 모두 설명할 수 있으면 완료입니다.
