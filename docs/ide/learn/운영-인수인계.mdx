# 재현 가능한 상태로 전달하기

IDE에서 저장한 것만으로 배포나 백업이 끝나지는 않습니다. 실행할 소스, 환경 설정, 모델 데이터와 검증 기록을 구분해 전달합니다.

## 1. 변경 범위 정리

모든 편집 내용을 저장하고 diff에서 화면·계약·메뉴가 같은 변경을 가리키는지 확인합니다. 설정 복제·배포 스크립트는 대상 파일을 덮어쓸 수 있으므로 생성 프로젝트의 README와 대상 환경을 먼저 확인하세요.

| 전달할 것 | 반드시 확인할 내용 |
|---|---|
| 소스와 계약 | 기준 커밋, 변경 파일, 필요한 모듈·런타임 |
| 실행 정보 | 작업 영역·서버 경로, 포트, 시작·중지 방법 |
| 데이터와 설정 | 스키마 변경, 데이터 원본 ID, 비밀 값의 관리 위치 |
| 검증 기록 | 대표 조회, 빈 결과, 실패 후 복구 결과 |
| 복구 정보 | 직전 정상 버전, 백업 위치, 복원 조건·담당자 |

키·암호 자체를 문서에 적지 않습니다. 접근 절차와 책임자만 기록하세요.

## 2. 저장 위치에 맞춰 백업

작업 영역은 Git·파일 백업, 모델은 화면의 JSON 백업, IDE의 영속 파일은 앱 종료 후 `data` 백업을 사용합니다. 구체적인 범위는 [저장 위치 표](../reference/파일과-저장-규칙.mdx#백업-대상)를 따르세요. Git만으로 WebView의 모델 데이터까지 보호되지는 않습니다.

:::warning 복원은 현재 데이터를 바꿀 수 있습니다

현재 상태를 먼저 백업하고 별도 검증 환경에서 복원하세요. 특히 SDLC의 **업무 복원**은 선택 업무의 문서를 교체합니다. 코드 복원과 DB 복원은 별개이며, 서버 재시작만으로 데이터가 되돌아오지 않습니다.

:::

## 3. 새 세션에서 검증

1. 기록한 경로로 작업 영역과 서버를 다시 확인합니다.
2. 메뉴를 통해 대표 화면을 열고 동일한 입력으로 조회합니다.
3. 응답과 로그를 확인하고, 모델을 사용했다면 백업 복원 후 문서와 연계를 확인합니다.
4. 미해결 오류와 수행하지 않은 시험은 `미완료`로 남깁니다.

다른 사람이 기록만 보고 정상 조회와 점검을 반복하면 이 학습 경로가 완료됩니다. 다음에는 [도메인 모델링](../guides/도메인-모델링.mdx)으로 설계 근거를 남기거나 [IDE 빠른 참조](../reference/index.mdx)에서 필요한 기능만 찾아보세요.
