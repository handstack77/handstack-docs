# 도메인 모델과 설계 근거 남기기

화면을 만들기 전에 데이터 구조와 사용자 흐름을 정리할 때 사용합니다. 모든 도구를 채우기보다 **지금 결정할 질문 하나**에 맞는 도구를 선택하세요.

## 데이터 구조부터 정리

1. **업무 > 도메인 모델 > 메타 정보 관리 > 엔티티 관리**에서 엔티티와 필드를 만듭니다.
2. 필드의 PK·NN·IX·AI·UI와 관계·열거형을 확인하고 저장합니다.
3. **앱 데이터베이스 관리**에서 앱 업무를 만들고 필요한 엔티티를 테이블로 가져옵니다.
4. DBML·ERD에서 관계를 확인합니다. 구조를 고치려면 엔티티 관리에서 수정한 뒤 다시 가져옵니다.

엔티티 관리의 **DBML 직접 편집**은 문법·참조 검사를 거쳐 모델에 반영합니다. 반면 앱 데이터베이스의 DBML은 읽기 전용입니다. **모델 저장이나 ERD 표시가 실제 DB 테이블 생성·변경을 뜻하지는 않습니다.** DB 적용은 대상 DB와 SQL을 따로 검증하세요.

## 질문에 맞는 SDLC 도구 선택

**업무 > 도메인 모델** 아래에서 찾습니다.

| 폴더 | 결정할 질문 | 도구 |
|---|---|---|
| 기획·계획 | 무엇을 만들고 먼저 할까? | ERRC, 중요도–불확실성, 친화도, 이해관계자, 고객 여정, 마인드맵, RICE |
| 기획·계획 | 누가 언제까지 할까? | WBS, Gantt, RACI, PERT 일정 예측 |
| 분석 | 사용자·업무·데이터는 어떻게 흐를까? | 유스케이스, 활동, DFD, BPMN |
| 설계 | 책임·상태·호출 관계는 무엇인가? | 클래스, 시퀀스, 객체, 상태 머신, 컴포넌트, 패키지 |
| 구현 | 어디에서 실행되고 통신하는가? | 배치, 네트워크 |

## 작은 실습: 조회 흐름 연결

1. 같은 **앱 업무**를 선택하고 유스케이스 문서에 ‘항목 검색’을 만듭니다.
2. 시퀀스 문서에 사용자 → 화면 → 거래 → DB의 요청·응답을 표현합니다.
3. **문서 연계**에서 두 문서를 연결하고 **문서 열기**로 이동합니다.
4. 각 문서를 저장하고 다시 열어 내용·관계가 유지되는지 확인합니다.

처음에는 **추천 구조**를 읽어 보고, 실제 작업에는 필요한 요소만 남기세요. 문서 연계는 근거를 추적하는 기능이며 코드 생성·서버 배포를 대신하지 않습니다. 여러 탭에서 같은 문서를 수정해 충돌하면 편집본을 새 복사본으로 보존합니다.

## PC를 옮기기 전에

모델은 작업 영역 파일과 별도로 관리됩니다. 엔티티, 앱 데이터베이스, SDLC의 백업 범위를 구분하세요. **업무 백업**은 선택 앱 업무의 SDLC 문서를 내보내며 테이블·관계 백업과는 별개입니다.

**업무 복원은 해당 업무의 SDLC 문서를 교체**하므로 현재 데이터를 먼저 백업합니다. [백업 대상 표](../reference/파일과-저장-규칙.mdx#백업-대상)를 확인한 뒤 별도 검증 환경에서 문서 목록과 연계가 복원되는지 시험하세요.
