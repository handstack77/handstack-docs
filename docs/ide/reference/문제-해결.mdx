# IDE 문제 해결

먼저 미저장 편집본을 보호하고 발생 시각, 작업 영역, 실행 대상, 최초 오류를 기록하세요. 설정을 여러 개 동시에 바꾸거나 사용자 데이터를 지우는 초기화부터 시작하지 않습니다.

## 파일이 보이지 않음

1. 작업 영역 경로와 트리 필터를 확인합니다.
2. **도구 > 환경설정 > 모양 > 숨김 항목 표시**와 `.gitignore`를 확인합니다.
3. 파일이 디스크에 있는지 확인하고 트리를 새로 고칩니다.

Function의 `.g.cs`, `.g.js`, `.g.py`는 생성 파일이라 트리에서 제외될 수 있습니다. 원본 계약을 찾으세요. 계약이 소스로 열리면 **개발** 탭에서 다시 열어 전용 편집기와 구분합니다.

## 저장하거나 다시 열 수 없음

현재 파일 경로·읽기 전용·쓰기 권한을 확인합니다. 같은 파일을 소스 탭, 전용 편집기, 외부 편집기에서 동시에 고쳤다면 먼저 각 편집본을 보존하세요. 다른 탭의 변경을 강제로 덮어쓰지 않습니다.

모델이 다른 PC에서 보이지 않는다면 프로젝트 파일이 아니라 WebView 저장소에 저장된 항목인지 [백업 대상](./파일과-저장-규칙.mdx#백업-대상)을 확인합니다.

## 서버와 미리보기

| 증상 | 먼저 볼 것 | 다음 확인 |
|---|---|---|
| IDE 시작 시 포트 설정 창 | 현재 IDE 포트 점유 | 다른 사용 가능한 포트 선택, 재시작 |
| 개발 서버 시작 실패 | rdy 루트·실행 파일·하단 서버 로그 | 포트, 계약 경로, 모듈 설정 |
| 화면 404 | 실제 열린 URL과 `wwwroot` 이후 경로 | 작업 영역 폴더명·대소문자·웹 루트 |
| 브라우저 열기 실패 | 서버 연동, Chrome/WorkView 설치·경로 | 기본 실행 URL과 최초 오류 |
| 터미널 열기 실패 | Photino 앱에서 실행 중인지 | 경로 존재·운영체제 권한 |

IDE 포트와 개발 서버 포트를 혼동하지 마세요. 보안 오류는 개발자 모드나 CSP를 해제해 덮지 말고 [설정과 보안](./설정과-보안.mdx)을 확인합니다.

## 거래와 화면 결과

| 증상 | 확인 순서 |
|---|---|
| 실행 버튼 비활성 | 계약 구성의 항목·서비스 선택 → 서버 연동 |
| 수정 전 결과가 나옴 | 계약 저장 → 서버의 계약 경로·재적재 상태 |
| HTTP 200인데 실패 | 응답의 오류·메시지 → 계약 ID·입력 맵 |
| SQL은 성공, 거래는 실패 | `.txn`의 서비스·입출력 → `.dbc` 구문·파라미터 |
| 거래는 성공, 화면은 비어 있음 | `outputs.dataFieldID`와 `syn-datafield` → 결과 컬럼·그리드 필드 |
| 연관 계약이 없거나 경고 | 파일 저장·목록 새로 고침 → 열린 작업 영역의 경로·ID |
| 예제 SQL의 키 타입 오류 | 실제 테이블 DDL → 계약의 키 생성·입력 타입 → README와의 차이 |

모든 이름은 대소문자까지 대조합니다. 스키마가 다르다고 운영 테이블을 삭제해 맞추지 마세요. 백업 후 별도의 실습 DB에서 일치하는 스키마·계약으로 검증합니다.

거래 이력정보에서는 발생 시간과 `GlobalID`로 요청을 좁힙니다. 이 화면은 실제 로그 DB를 조회하므로 로그가 없다고 거래가 실행되지 않았다고 단정하지 말고 로그 수집 설정·DB 대상·시간 조건도 확인하세요.

## 중단점이 잡히지 않음

1. 하단 **디버그**의 Attach 대상 PID·실행 파일·포트가 원하는 ack인지 확인합니다.
2. 실행 바이너리와 같은 빌드의 PDB가 함께 있는지 확인합니다.
3. PDB의 소스 경로와 작업 영역 소스가 일치하는지 확인합니다.
4. Release 최적화 때문에 위치가 달라질 수 있으므로 재현용 Debug 빌드를 검토합니다.

실행 파일 폴더와 소스 폴더 자체가 같을 필요는 없습니다. 중요한 것은 바이너리·PDB·소스의 일치입니다.

## 복구 후 확인

원래 실패했던 입력으로 재시험하고 정상 결과·로그를 남깁니다. 공유할 기록에는 재현 순서와 비식별 오류만 포함하고 키·쿠키·연결 문자열은 제거하세요. 서버 자체 문제는 [HandStack 문제 해결](/docs/guides/문제-해결)로 이어서 확인합니다.
