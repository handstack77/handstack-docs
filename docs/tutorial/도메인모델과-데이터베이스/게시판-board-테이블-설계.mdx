# 게시판 Board 테이블 설계

> [주제 목차](/docs/tutorial/도메인모델과-데이터베이스/) · 이전: [데이터 모델 개념](/docs/tutorial/도메인모델과-데이터베이스/데이터-모델-개념) · 다음: [데이터베이스 연결과 검증](/docs/tutorial/도메인모델과-데이터베이스/데이터베이스-연결과-검증)

이 문서의 결과: 게시판 화면 요구사항에서 `Board` 테이블의 컬럼과 타입을 도출한다.

## 화면 요구사항

- 게시글은 분류, 제목, 내용, 작성자, 작성일시를 가집니다.
- 목록 화면은 분류·기간·제목으로 조건 조회하고 최신순으로 정렬합니다.
- 상세 화면은 조회한 글을 수정·삭제할 수 있습니다.

이 요구사항은 [게시판 프로젝트 시작하기](/docs/startup/handsonlab/게시판-프로젝트-시작하기)의 사용자 스토리를 그대로 재사용합니다.

## 설계표

| 컬럼명 | 데이터 타입 | 설명 | 필수 |
|---|---|---|:-:|
| ID | INTEGER (자동증가, 기본키) | 게시글 고유 번호 | O |
| Category | TEXT | 게시글 분류 | O |
| Title | TEXT | 제목 | O |
| Content | TEXT | 본문 | O |
| Author | TEXT | 작성자 | O |
| DatePosted | TEXT | 작성 일시 | O |

## DDL

```sql
CREATE TABLE IF NOT EXISTS Board (
  ID INTEGER PRIMARY KEY AUTOINCREMENT,
  Category TEXT,
  Title TEXT,
  Content TEXT,
  Author TEXT,
  DatePosted TEXT
);
```

## 자주 하는 오해

**"ID는 화면에 보여주는 게시글 번호와 같은 건가요?"**
같은 값을 보여줄 수는 있지만 개념은 다릅니다. `ID`는 데이터베이스가 관리하는 내부 키이고, 화면에 노출할 업무 식별자가 별도로 필요하면 다른 컬럼으로 분리하는 것이 안전합니다. 이 예제에서는 단순화를 위해 `ID`를 그대로 노출합니다.
