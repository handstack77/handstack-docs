# 인수인계 체크리스트

> [주제 목차](/docs/tutorial/모니터링과-운영인수인계/) · 이전: [서버 프로세스 관리](/docs/tutorial/모니터링과-운영인수인계/서버프로세스-관리)

이 문서의 결과: 다른 담당자가 문서만 보고 시작·점검·복구할 수 있는 인수인계 문서를 작성한다.

## 인수인계가 끝났다고 볼 수 있는 기준

다른 담당자가 문서만 보고 시작·점검·복구할 수 있어야 인수인계가 끝난 것으로 봅니다. 직접 시연하며 설명하는 것만으로는 부족하며, 그 사람이 자리를 비웠을 때도 다른 사람이 같은 절차를 재현할 수 있어야 합니다.

## 인수인계 체크리스트

- [ ] 서버 시작/중지 절차와 정상 기동 확인 방법
- [ ] 환경별 설정 파일 위치와 `RunningEnvironment` 값
- [ ] 주요 장애 시 확인할 로그 경로와 순서
- [ ] 백업 대상(데이터베이스 파일, 계약 디렉토리)과 복구 절차
- [ ] 공개 거래(`Authorize: false`) 목록과 담당자 — [11. 환경설정과 보안](/docs/tutorial/환경설정과-보안/공개거래와-인증-점검)에서 작성한 표를 그대로 사용합니다

## 게시판 예제로 인수인계 문서 작성해 보기

지금까지 만든 게시판(`BOD` 모듈) 프로젝트를 기준으로 위 체크리스트를 채워 봅니다.

| 항목 | 채울 내용 예시 |
|---|---|
| 시작/중지 | `ack` 실행 경로, `handstack stop --pid` 사용법 |
| 설정 파일 | 어떤 `appsettings` 프리셋을 쓰는지, 위치 |
| 장애 로그 | transact/dbclient 로그 경로, 확인 순서 |
| 백업 대상 | `board.db` 파일 위치, 백업 주기 |
| 공개 거래 | `BOD010.LD01`, `BOD012.GD01` 등과 공개 이유 |

## 검증: 다른 사람에게 문서만 넘겨 보기

가능하다면 이 문서만 가지고 다른 사람(또는 스스로 며칠 뒤)이 다음을 재현할 수 있는지 확인합니다.

1. 서버를 시작한다.
2. 게시판 화면에 접속해 정상 동작을 확인한다.
3. 의도적으로 만든 오류 상황([10. 테스트와 디버깅](/docs/tutorial/테스트와-디버깅/결함-재현과-원인분석)의 재현 절차)을 진단한다.
4. 서버를 재기동한다.

네 가지를 문서만 보고 해낼 수 있다면 인수인계 문서가 충분한 것입니다. 막히는 지점이 있다면 그 부분을 보완합니다.
