# 08. transact 거래 계약

화면과 SQL을 거래로 연결하고, 요청·응답 전문과 데이터 맵을 확인하는 방법을 배웁니다. 이 주제를 마치면 게시판 화면의 조회·저장이 처음부터 끝까지 동작합니다.

## 이 주제를 배우면

화면이 왜 SQL을 직접 부르지 않고 transact 계약을 거치는지 설명하고, 거래가 성공했는데 화면이 비는 문제를 스스로 진단할 수 있게 됩니다.

## 선수 지식

- [07. dbclient SQL 계약](/docs/tutorial/dbclient-SQL계약/) 완료
- [06. 화면 동작과 거래 연결](/docs/tutorial/화면동작과-거래연결/)에서 만든 `transactionAction` 호출

## 학습 목표

- transact 계약이 화면과 SQL 사이에 존재하는 이유를 설명합니다.
- `BOD010`/`BOD011`/`BOD012` 거래 계약을 작성해 전체 CRUD를 연결합니다.
- 데이터 맵 이름 불일치로 화면이 비는 문제를 진단합니다.

## 완료 조건

- [ ] `BOD010.json`, `BOD011.json`, `BOD012.json` 거래 계약을 작성했습니다.
- [ ] 화면에서 조회 → 등록 → 목록 갱신까지 전체 흐름이 동작하는 것을 확인했습니다.
- [ ] 데이터 맵 이름 불일치로 화면이 비는 상황을 한 번 재현하고 원인을 찾아봤습니다.
