# 07. dbclient SQL 계약

SQL을 dbclient 계약으로 관리하고, 화면 없이 단독으로 검증하는 방법을 배웁니다.

## 이 주제를 배우면

게시판 조회·등록·수정·삭제 SQL을 계약 파일로 작성하고, 화면을 만들기 전에 SQL만 따로 검증할 수 있게 됩니다.

## 선수 지식

- [04. 도메인 모델과 데이터베이스](/docs/tutorial/도메인모델과-데이터베이스/)에서 만든 `Board` 테이블

## 학습 목표

- dbclient 계약(XML)의 `header`/`statement`/`param` 구조를 설명합니다.
- `BOD010`/`BOD011`/`BOD012`의 CRUD SQL 계약을 작성합니다.
- 화면 없이 SQL 실행 결과를 단독으로 검증하고, 동적 SQL의 필요성을 판단합니다.

## 학습 경로

| 순서 | 문서 | 완료 후 남길 결과 |
|---|---|---|
| 1 | [dbclient 계약 개념](dbclient-계약-개념) | 계약 구조와 파라미터 바인딩 원리를 설명한다 |
| 2 | [CRUD 계약 작성](CRUD-계약-작성) | `BOD010`/`BOD011`/`BOD012` SQL 계약을 작성한다 |
| 3 | [단독 검증과 동적 SQL](단독-검증과-동적SQL) | 화면 없이 SQL을 검증하고 동적 SQL 필요 여부를 판단한다 |

## 완료 조건

- [ ] `BOD010.xml`에 목록 조회(`LD01`) 계약을 작성했습니다.
- [ ] `BOD011.xml`에 등록(`ID01`) 계약을 작성했습니다.
- [ ] `BOD012.xml`에 조회·수정·삭제(`GD01`, `UD01`, `DD01`) 계약을 작성했습니다.
- [ ] 화면 없이 SQL 실행 결과만으로 데이터가 정확한지 확인했습니다.
