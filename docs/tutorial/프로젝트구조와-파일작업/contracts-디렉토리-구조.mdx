# contracts 디렉토리 구조

> [주제 목차](/docs/tutorial/프로젝트구조와-파일작업/) · 다음: [편집과 저장 규칙](/docs/tutorial/프로젝트구조와-파일작업/편집과-저장-규칙)

이 문서의 결과: `contracts` 아래 5개 디렉토리의 역할과 항목 ID 규칙을 설명한다.

## 5개 디렉토리

`%HANDSTACK_HOME%\contracts`를 편집기로 열면 다음 디렉토리가 있습니다. 자세한 예시는 [소스 디렉토리 구조](/docs/startup/learning/소스-디렉토리-구조)에서 확인할 수 있습니다.

|디렉토리|담당 모듈|설명|
|---|---|---|
|`wwwroot`|wwwroot|화면 HTML/JS, 공용 정적 자산|
|`transact`|transact|거래 요청 검증·라우팅 계약 (`.json`)|
|`dbclient`|dbclient|SQL을 XML로 관리하는 계약 (`.xml`)|
|`function`|function|C#/Node.js 기반 서버 함수|
|`repository`|repository|파일 업로드/다운로드 저장소 설정|

## 항목 ID 규칙: 프로그램 ID &gt; 프로젝트 ID &gt; 파일 ID

```text
contracts
├─wwwroot
│  └─HDS          <- 프로그램 ID (ApplicationID)
│      └─BOD      <- 프로젝트 ID (ProjectID)
│          ├─BOD010.html   <- 파일 ID (화면/거래 단위)
│          ├─BOD010.js
│          ├─BOD011.html
│          └─BOD011.js
```

같은 규칙이 `transact`, `dbclient`에도 동일하게 적용됩니다. 하나의 화면/기능은 세 모듈에서 같은 항목 ID로 관리되어 유지보수·인수인계 비용을 줄입니다.

## 식별자 읽기

`HDS`는 애플리케이션, `BOD`는 프로젝트, `BOD010`은 화면·거래, `LD01`은 목록 조회 기능을 나타냅니다. 예제의 `LD01` 명명 순서는 **L(List) + D(Database) + 01**입니다.

정확한 식별자와 파일별 대응은 [식별자와 파일 경로](/docs/reference/식별자와-파일-경로)에서 확인하세요. 서버 실행 대상은 ID의 글자만이 아니라 계약의 `CommandType` 설정으로 결정됩니다.

## 직접 찾아보기

실행 중인 BOD 예제에서 `BOD010.html`, `BOD010.js`, `BOD010.json`, `BOD010.xml`을 찾아 각 파일의 역할을 설명해 보세요. 파일이 나뉘는 이유는 화면 배치, 동작, 거래 규칙, SQL을 따로 변경하기 위해서입니다.
