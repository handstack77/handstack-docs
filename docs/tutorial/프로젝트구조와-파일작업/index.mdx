# 02. 프로젝트 구조와 파일 작업

`contracts` 디렉토리 구조를 익히고, 화면·계약 파일을 편집기에서 안전하게 편집·저장·복구하는 방법을 배웁니다.

## 이 주제를 배우면

새 화면이나 계약 파일을 어느 디렉토리에 만들어야 하는지, 저장한 파일이 실제로 반영됐는지, 실수로 망가뜨렸을 때 어떻게 되돌리는지 스스로 판단할 수 있게 됩니다.

## 선수 지식

- [01. HandStack 기초 개념](/docs/tutorial/handstack-기초개념/) 완료
- 파일 탐색기와 텍스트 편집기(VS Code 등) 사용 경험
- 기본적인 Git 명령어(`status`, `diff`, `checkout`)

## 학습 목표

- `contracts` 아래 5개 디렉토리(`dbclient`, `function`, `repository`, `transact`, `wwwroot`)의 역할을 구분합니다.
- 항목 ID 규칙(프로그램 ID > 프로젝트 ID > 파일 ID)에 따라 새 파일을 어디에 만들지 결정합니다.
- 저장한 파일이 실제로 반영됐는지 확인하는 방법을 압니다.
- 실수로 파일을 손상시켰을 때 Git으로 되돌립니다.

## 학습 경로

| 순서 | 문서 | 완료 후 남길 결과 |
|---|---|---|
| 1 | [contracts 디렉토리 구조](/docs/tutorial/프로젝트구조와-파일작업/contracts-디렉토리-구조) | 5개 디렉토리와 항목 ID 규칙을 설명한다 |
| 2 | [편집과 저장 규칙](/docs/tutorial/프로젝트구조와-파일작업/편집과-저장-규칙) | 파일 인코딩·저장·반영 확인 절차를 수행한다 |
| 3 | [변경 복구와 백업](/docs/tutorial/프로젝트구조와-파일작업/변경-복구와-백업) | Git으로 손상된 파일을 이전 상태로 되돌린다 |

## 완료 조건

- [ ] `contracts` 아래 5개 디렉토리의 역할을 각각 한 문장으로 설명했습니다.
- [ ] 항목 ID 6자리(`BOD010`)의 각 자리 의미를 설명했습니다.
- [ ] 텍스트 파일을 수정하고 저장한 뒤 브라우저 새로고침으로 반영을 확인했습니다.
- [ ] 의도적으로 파일을 깨뜨린 뒤 `git checkout`으로 복구했습니다.
