# 편집과 저장 규칙

> [주제 목차](/docs/tutorial/프로젝트구조와-파일작업/) · 이전: [contracts 디렉토리 구조](/docs/tutorial/프로젝트구조와-파일작업/contracts-디렉토리-구조) · 다음: [변경 복구와 백업](/docs/tutorial/프로젝트구조와-파일작업/변경-복구와-백업)

이 문서의 결과: 파일을 수정·저장한 뒤 실제 반영 여부를 확인하는 절차를 수행한다.

## 시작 조건

- [03. 프로젝트와 개발 서버](/docs/tutorial/프로젝트와-개발서버/)에서 안내할 개발 서버가 실행 중이거나, 실습용 예제 프로젝트가 로컬에 준비돼 있어야 합니다. 이 문서는 편집·저장 규칙만 먼저 익히는 것이 목적이며, 서버가 없다면 파일 내용만으로 구조를 확인해도 무방합니다.

## 편집기 선택과 인코딩

- HTML/JS/XML/JSON 파일은 UTF-8 인코딩으로 저장합니다. 다른 인코딩으로 저장하면 한글이 깨지거나 계약 파싱이 실패합니다.
- VS Code, Notepad++ 등 일반 텍스트 편집기면 충분합니다. 별도의 컴파일이나 빌드 도구가 필요하지 않습니다.
- 줄바꿈(EOL) 문자는 저장소의 `.gitattributes`나 기존 파일 관례를 따릅니다. 임의로 CRLF/LF를 섞지 않습니다.

## 저장 후 반영 확인하기

HandStack은 정적 파일(html/js)과 계약 파일을 서버 재시작 없이 즉시 읽는 경우가 많지만, 계약 종류나 서버 설정에 따라 캐시 동작이 다를 수 있습니다. 다음 순서로 반영 여부를 확인합니다.

1. 파일을 저장합니다.
2. 브라우저에서 해당 화면을 새로고침합니다.
3. 브라우저 개발자 도구의 네트워크 탭에서 실제로 새 파일이 요청됐는지 확인합니다(캐시된 이전 버전이 아닌지).
4. 계약 파일(json/xml)을 수정했다면 거래를 다시 실행해 응답이 바뀌었는지 확인합니다.

반영되지 않는다면 다음을 의심합니다.

| 증상 | 확인할 것 |
|---|---|
| 화면이 그대로 | 브라우저 캐시, 저장 경로(항목 ID·디렉토리)가 맞는지 |
| 거래 결과가 그대로 | dbclient/transact 계약의 문법 오류, 서버 로그 |
| 오류 화면 표시 | XML/JSON 문법 오류(따옴표, 태그 닫힘) |

## 저장 전 점검 체크리스트

- [ ] 항목 ID가 화면·계약·SQL 세 곳에서 동일한지 확인했습니다.
- [ ] JSON/XML 파일을 저장하기 전 문법 오류가 없는지 편집기의 문법 강조로 확인했습니다.
- [ ] 실제 운영 값(비밀번호, 연결 문자열, API Key)을 예제 파일에 남기지 않았습니다.

## 이것만 기억하세요

1. **UTF-8로 저장하고, 저장 후에는 반드시 브라우저에서 반영을 눈으로 확인한다.**
2. **화면이 그대로면 캐시를, 거래 결과가 그대로면 계약 문법을 먼저 의심한다.**
