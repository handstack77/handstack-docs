# 10. 테스트와 디버깅

GlobalID와 거래 이력으로 실패 원인을 순서대로 좁혀 가는 방법을 배웁니다.

## 이 주제를 배우면

"거래가 실패했다"는 보고를 받았을 때 화면·transact·dbclient·function 중 어디부터 볼지, 어떤 근거로 판단할지 스스로 정할 수 있게 됩니다.

## 선수 지식

- [01. HandStack 기초 개념](/docs/tutorial/handstack-기초개념/)의 [요청흐름 이해](/docs/tutorial/handstack-기초개념/요청흐름-이해)
- [08. transact 거래 계약](/docs/tutorial/transact-거래계약/)

## 학습 목표

- 계층별 진단 도구(네트워크 탭, 거래 이력, 모듈 로그)를 순서대로 사용합니다.
- GlobalID로 실패한 거래 하나를 끝까지 추적합니다.
- 회귀를 확인하는 습관으로 릴리스 여부를 판단합니다.

## 학습 경로

| 순서 | 문서 | 완료 후 남길 결과 |
|---|---|---|
| 1 | [진단 도구와 계층](진단-도구와-계층) | 계층별 도구와 확인 순서를 설명한다 |
| 2 | [결함 재현과 원인 분석](결함-재현과-원인분석) | GlobalID로 실패 거래를 추적해 원인을 찾는다 |
| 3 | [회귀 확인 습관](회귀-확인-습관) | 수정 전후 케이스를 비교해 회귀를 확인한다 |

## 완료 조건

- [ ] GlobalID로 거래 하나의 시작부터 끝까지 추적했습니다.
- [ ] 데이터 맵 이름 불일치로 인한 "성공했는데 화면이 빈" 상황을 진단했습니다.
- [ ] 의도적으로 계약 파일에 오류를 넣고 오류 메시지를 확인한 뒤 되돌렸습니다.
