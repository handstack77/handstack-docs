# 조회 조건 바꾸기

[첫 조회](/docs/tutorial/첫-조회)에서 사용한 게시판의 제목 검색 안내를 바꾸고, 입력이 거래로 전달되는 과정을 확인합니다.

## 입력 요소 수정

실행 중인 예제의 `BOD010.html`을 편집기로 여세요. [계약 파일 위치](/docs/reference/식별자와-파일-경로)를 확인하고 원본을 복구할 수 있도록 변경 전 내용을 보관합니다.

`id="txtTitle"`인 기존 입력 요소에 다음 속성만 추가하세요. 같은 입력을 새로 만들거나 `id`를 바꾸지 않습니다.

~~~html
placeholder="제목의 일부를 입력하세요"
~~~

브라우저에서 새로고침했을 때 입력 안내가 달라지면 편집한 파일이 실제 화면에 반영된 것입니다.

## 입력과 조회 연결 읽기

제목 입력에는 다음 설정이 있습니다.

~~~html
syn-datafield="Title"
syn-options="{editType: 'text', belongID: ['LD01']}"
~~~

`Title`은 전달할 데이터 이름, `LD01`은 이 입력을 사용할 거래 이름입니다. `BOD010.js`의 조회 이벤트는 다음과 같습니다.

~~~js
btnSearch_click(evt) {
    syn.$w.transactionAction('LD01');
}
~~~

이 코드는 기존 객체 안의 메서드 발췌입니다. 별도의 JS 파일로 실행하지 마세요. 정확한 구문과 옵션은 [거래 호출 레퍼런스](/docs/reference/거래-호출)에 있습니다.

## 직접 확인

1. 목록에 있는 제목의 일부를 입력하고 조회합니다.
2. 표시된 제목에 입력한 문자열이 포함되는지 확인합니다.
3. 존재하지 않는 제목을 입력해 빈 목록과 거래 오류를 구분합니다.
4. 제목을 비우고 조회해 원래 결과로 돌아옵니다.

브라우저 개발자 도구의 Network에서 거래 요청과 응답도 비교해 보세요. 입력값이 바뀌었는데 결과가 같다면 날짜·분류 조건과 실행 중인 계약을 확인합니다.

## 다음 수준으로 확장

이제 `Category` 입력과 `LD01`의 관계를 직접 찾아 같은 방법으로 설명해 보세요. 파일을 찾아 설명할 수 있으면 다음 [프로젝트 준비](/docs/tutorial/프로젝트와-개발서버/)에서 화면을 직접 만드는 과정으로 진행합니다.

직접 구현하는 순서는 **프로젝트 준비 → DB 준비 → 화면 → 이벤트 → SQL 계약 → 거래 연결**입니다. 전체 경로는 [따라 만들기](/docs/tutorial/)에서 확인하세요.
