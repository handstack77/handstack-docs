## 1. 릴리즈 기록

매 배포마다 아래를 파일(예: `release-record.json`)로 남기고 CI 산출물로 보관한다. **[문서]** 공식 빌드·릴리즈 절차의 기록 항목을 기준으로 한다.

| 항목 | 내용 |
|---|---|
| 빌드 시각 | UTC 권장 |
| 브랜치·커밋 ID | 소스 저장소 |
| 매개변수 | `publish` 인자(os/action/configuration/arch), 빌드 구성 |
| 포함 모듈 | 모듈 이름과 버전(`module.json` `Version`) |
| 대상 환경 | `ACK_ENVIRONMENT`(D/S/P), 서버/컨테이너 식별 |
| 적용 설정 | 사용한 설정 파일 이름(값은 기록하지 않음) |
| 패키지 | 업데이트 ZIP 이름·SHA-256, 이미지 태그·다이제스트 |
| 배포 후 확인 | 항목별 결과 |
| 승인자·시각 | 운영 반영 승인 |

기록에 비밀 값을 넣지 않는다. 같은 명령으로 산출물을 다시 만들 수 있는지(재현성)도 확인한다.

## 2. 배포 후 확인

순서대로 확인하고 하나라도 실패하면 롤백 판단으로 넘어간다.

1. 프로세스/컨테이너 기동, 최근 로그의 오류(`${HANDSTACK_HOME}/log/app*.log`).
2. `GET /checkip` (프록시 뒤에서도 응답 확인).
3. 버전: `GET /manifest`(현재 `version.json` 값), 업데이트 방식이면 `app/version.json`, `log/update/updater.log`, `deploy`의 `storage/errors` 없음.
4. 대표 정적 파일 응답과 로그인/메뉴 진입.
5. 대표 조회 거래 1건 + 변경 거래 1건(테스트 데이터). 변경 거래는 운영에서 하지 않고 검증 환경에서 한다.
6. 이번 변경이 건드린 화면·거래(`hs_inspect.py` 연결표 기준)를 직접 호출.
7. 관리 API는 승인된 호출자와 키로만(해시 값 전달, 인증을 우회하지 않음).

## 3. 롤백 계획 (배포 전에 작성)

| 방식 | 되돌릴 대상 | 절차 개요 |
|---|---|---|
| 폴더 반영 | 반영 전에 만든 `app`·`modules/{모듈}`·`contracts`·설정 사본 | 서비스 정지 → 사본 복원 → 시작 → 확인 |
| 업데이트 패키지 | `updater`가 만든 `backup/<시각>/<버전>/…` | 서비스 정지 → 백업 파일을 원위치로 복원 → `app/version.json`을 이전 버전으로 되돌림 → 시작. `deploy`에 이전 버전만 최신이 되게 하려면 상위 버전 ZIP을 카탈로그에서 제외해야 하는데 그 관리 기능은 확인하지 못했으므로 사용 환경에서 확인 |
| Docker | 이전 이미지 태그 + 이전 볼륨 상태 | 컨테이너 교체 → 볼륨 내용 복원 → 확인 |

공통 주의:
- DB 변경(DDL/DML)이 포함되면 코드 롤백만으로 복구되지 않는다. 변경 스크립트와 되돌리는 스크립트(또는 복구 시점)를 함께 준비하고, 되돌릴 수 없는 변경은 배포 승인 항목에 올린다.
- 백업은 만들었다는 사실만으로 충분하지 않다. 비운영 환경에서 복원을 연습한다.
- 롤백 후에도 5절 배포 후 확인을 다시 수행하고 원인 분석(`handstack-troubleshooting`)을 기록한다.

## 4. 비밀과 접근 관리

- CI 도구의 자격 증명 저장소에 둔다: 소스 저장소 계정, 배포 키(`X-Deploy-Key`), 원격 서버 SSH 키, 관리 API 해시 값, 외부 API 키.
- 원격 제어 스크립트(CI 잡을 호출하는 도구)에 API 토큰·계정·서버 주소를 **코드에 쓰지 않는다.** 환경 변수/자격 증명 저장소에서 읽는다.
- 이미 문서·스크립트에 평문으로 남은 토큰은 폐기·재발급하고 저장소 이력 정리 여부를 별도로 판단한다. `pipeline_lint.py`의 `secret` 결과가 후보 목록이다.
- 운영 잡은 트리거를 수동 또는 승인 단계로 둔다. 운영 서버에 쓰는 계정은 최소 권한으로 한다.
- 러너와 대상 서버 사이는 키 기반 인증을 쓰고 비밀번호를 스크립트에 넣지 않는다.
- 관리 호스트(`deploy`, `agent`)의 키는 비워 두지 않는다. 모듈 `AllowClientIP` 기본값 `*`는 개발용이다.

## 5. 운영 체크리스트

- [ ] 선택한 배포 방식이 환경마다 하나다
- [ ] 러너의 `HANDSTACK_HOME`이 운영 홈과 분리됐다(`publish`/PostBuild 부작용)
- [ ] 공유 `contracts`를 미러링하지 않는다
- [ ] 대상 환경 ↔ 설정 파일이 일치한다(운영 잡에 개발 설정 없음)
- [ ] 비밀이 저장소/스크립트/문서에 평문으로 없다
- [ ] 격리 스모크(`/checkip` + 대표 거래)를 통과한 산출물만 배포한다
- [ ] 운영 반영에 승인 단계가 있다
- [ ] 릴리즈 기록이 남고 같은 명령으로 재현된다
- [ ] 배포 전 백업과 복원 절차를 리허설했다
- [ ] 배포 후 확인 결과와 롤백 결정 기준이 기록된다
