# 화면 상태 설계 (조회·저장 업무 화면)

정상 화면만큼 **빈 결과, 거절, 실패, 결과 불명** 상태를 설계한다. "오류가 발생했습니다"만 보여 주면 사용자는 입력을 고쳐야 하는지, 다시 눌러도 되는지 알 수 없다.

## 목차
1. 상태 표
2. 오류 종류 구분
3. HandStack 구현 연결
4. 입력·확인 흐름 규칙
5. 접근성·키보드
6. 설계 시 와이어프레임에 붙일 정보

## 1. 상태 표

화면마다 아래 상태를 모두 정의하고 구현 후 하나씩 재현해 본다.

| 상태 | 사용자에게 전달할 것 | 행동·포커스 처리 |
|---|---|---|
| 초기 | 입력/조회 방법, 필수 조건 | 첫 입력에 접근 가능한 레이블, 기본 포커스 |
| 조회·저장 중 | 어떤 작업이 진행 중인지 | 중복 요청 차단(버튼 비활성), 입력값 보존 |
| 결과 없음 | 조건에 맞는 데이터가 없음(오류 아님) | 조건 수정 가능, 빈 그리드가 정상 상태임을 표시 |
| 입력 오류 | 어느 필드가 왜 잘못됐는지 | 해당 필드로 포커스, 색만으로 구분하지 않음 |
| 업무 거절 | 대표 사유와 다음 행동 | 입력 유지, 해결 후 재시도 가능 |
| 성공 | 확정된 결과(ID, 기한 등 서버 값) | 성공 결과 유지, 다음 업무로 이동 가능 |
| 일시 장애 | 잠시 후 재시도 안내 | 입력 유지 |
| 결과 불명(응답 유실) | 처리 여부를 확인 중이라는 안내 | 같은 내용을 다시 저장하지 말고 조회로 결과 확인 후 재시도 |

## 2. 오류 종류 구분

- **입력 오류**: 화면이 먼저 잡는다(필수·형식). 서버도 같은 조건을 다시 검사한다.
- **업무 거절**: 서버 규칙 위반. 계약의 `Exception` 출력(`Error`/`Message`)이나 규칙 사유 코드로 받아 사유별 메시지를 보여 준다. 규칙 ID를 로그/메시지 코드로 남기면 추적이 쉽다(`handstack-rules-and-verification`의 규칙 표).
- **시스템 오류**: 권한·계약·SQL 오류, 서버 `exceptionText`. 사용자에게는 일반 메시지, 상세는 로그/`GlobalID`로.
- **결과 불명**: 응답을 받지 못함. 실패로 단정하지 않는다.

## 3. HandStack 구현 연결

- 저장 성공 판정은 응답의 `Exception.Error` 같은 계약 값으로 한다(응답이 왔다는 사실만으로 성공 처리하지 않는다). 변환은 `$string.toBoolean`.
- 빈 결과: Form 출력은 **0행이면 갱신되지 않아** 이전 값이 남을 수 있다. 조회 시작 시 폼/그리드를 비우거나 `clear` 동작을 확인한다.
- callback이 `undefined`를 반환하면 `afterTransaction`이 호출되지 않아 알림·포커스 처리가 빠진다([바인딩 규칙](binding-rules.md) 4절). 매핑 오류(`errorText`)는 콜백 없이 로그만 남기므로 화면이 "아무 일도 안 일어난" 상태가 된다 — 개발 중 콘솔을 확인한다.
- `beforeTransaction`이 `false`를 반환하면 요청하지 않는다: 입력 오류 안내는 여기서 한다.
- 중복 클릭 방지, 통신 실패·타임아웃 시 콜백 호출 여부는 프레임워크 버전과 모듈의 `syn.domain.js`에 따라 다르다. **프로젝트에서 실제로 끊어 보고(오프라인, 느린 응답) 확인한 뒤** 화면 코드를 쓴다. 확인하지 못했으면 보고서에 적는다.
- 삭제 등 되돌릴 수 없는 작업은 확인 대화상자를 거치고, 확인 이후 실패/성공을 구분해 표시한다.

## 4. 입력·확인 흐름 규칙

- 대상(회원, 품목 등)을 조회로 확인한 뒤 저장하는 화면에서, 대상 입력을 바꾸면 **이전 확인 결과를 무효화**해 다른 대상을 확인한 정보로 저장하지 않게 한다.
- 화면의 "가능" 표시는 확인 시점의 정보다. 저장 서비스가 저장 직전 규칙을 다시 검사한다.
- 예상 값(예: 계산된 기한)은 확인용 표시이고, 확정 값은 저장 응답으로 갱신한다.
- 오류 후에는 사용자가 입력을 다시 하지 않아도 되게 값을 유지한다.

## 5. 접근성·키보드

- 모든 입력에 의미 있는 레이블, 필수/오류를 색 외 텍스트·아이콘으로도 표시.
- 키보드만으로 입력 → 확인 → 결과 영역까지 이동 가능, 오류 발생 후 포커스를 해당 필드나 결과 영역으로.
- 좁은 화면에서는 단순 축소 대신 주요 행동과 정보가 읽히는지 확인(디자인 시스템 문서의 반응형 지침).

## 6. 설계 시 와이어프레임에 붙일 정보

화면 ID, 관련 규칙 ID, 입력 제약, 위 상태 표의 항목별 문구, 확인할 질문. 대표 과업("이 대상으로 이 처리를 하고 결과를 확인")으로 사용자에게 시연해 막히는 지점을 관찰한다.
