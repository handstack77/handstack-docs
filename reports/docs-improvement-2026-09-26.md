# HandStack 문서 개선 기록

검토일: 2026-09-26. 대상: `docs/`, 문서 홈, 메뉴와 관련 빌드 설정.

## 범위와 근거

기존 356개 Markdown/MDX 문서의 구조를 조사하고, 입문→게시판→레퍼런스 경로의 대표 본문을 집중 검토했습니다. 이번 변경으로 문서 10개를 추가해 사이트 문서는 366개입니다. 모든 본문·코드·운영 절차를 다시 검증하거나 전면 개작한 작업은 아닙니다.

가상 페르소나는 **김민수: 웹 개발 2년 차, HTML·JavaScript·SQL 사용 가능, HandStack 처음, Windows 11에서 게시판 조회 화면 구현**입니다. 설문 응답자 원자료나 실제 사용자 관찰 수치는 제공되지 않았으므로, 아래 결과는 브라우저 기반 문서 검토이며 사용자 실험 결과가 아닙니다.

구조는 [Diátaxis](https://diataxis.fr/)의 학습·작업·참조·설명 구분, 문체는 [Google 개발자 문서 스타일 가이드](https://developers.google.com/style/highlights)의 직접적인 표현과 설명적인 링크 원칙을 참고했습니다. 이를 특정 연도에 새로 등장한 유행이라고 주장하지 않습니다.

## 페르소나 관점의 개선

| 작업 | 확인한 문제 | 반영 내용 | 확인할 결과 |
|---|---|---|---|
| 처음 시작 | 홈의 짧은 완료 시간과 긴 설치 안내의 기대 차이 | 시간 단정 제거, 실행·예제·참조 진입점 | 준비 여부에 맞는 시작점 선택 |
| 설치 준비 | 일반 도구 설치와 HandStack 구성이 섞임 | 공식 설치 링크·필수 선택·확인 명령 중심으로 축약 | SDK/Runtime, 최소 버전/지원 버전 구분 |
| 서버 실행 후 진행 | 빠른 시작의 다음 문서가 CLI | 첫 조회 → 조회 조건 변경으로 연결 | 실행한 예제에서 바로 작은 성공 경험 |
| 학습 경로 찾기 | 메뉴가 전체 경로 대신 첫 분류로 연결, 주제 소개 중복 | `/docs/tutorial/` 연결, 12개 분류를 소개 문서로 직접 연결 | 중간 자동 목차 없이 주제 확인 |
| 직접 구현 | 빠른 경로에서 DB 준비를 건너뛰지만 화면 실습은 DB를 전제 | 프로젝트 → DB → 화면 → 이벤트 → SQL → 거래 연결 | 필수 선행 작업 누락 없음 |
| 목록 작성 | 날짜 조건·코드 삽입 위치·실행 주소 부족 | 날짜 입력, 기본 HTML 위치, URL, 화면 표시 기준 추가 | 복사한 코드의 위치와 확인 방법 명확 |
| DB 연결 | 임의 `board.db`와 DB01 연결의 관계 불명확 | 실제 설정의 SQLite 파일 확인 후 DDL·데이터 준비 | SQL 편집기와 HandStack이 같은 DB 사용 |
| 거래 이해 | HTML/JS/JSON 세 곳의 이름을 모두 같게 하라는 설명 | 컨트롤 이름과 계약 출력 형식·순서 구분 | Dynamic/Grid 계약과 모순 없음 |
| 예제 초기화 | 긴 예제 끝에 실행 경로, 초기화의 영향 불명확 | 첫 조회 분리, Board 데이터·ID 삭제 경고 | 실습 환경과 업무 데이터 구분 |
| API 찾기 | 참고하기의 메뉴·푸터 목적지 불일치 | API·설정 참조로 통일, 작업/식별자 색인 | 이름을 알면 대표 명세로 바로 이동 |

## 배치·분리 매핑

기존 문서 파일명과 URL은 유지했습니다. 메뉴는 디렉터리 이름이 아닌 독자의 목적에 맞춰 연결합니다.

| 기존 자료 | 새 탐색 위치 | 처리 |
|---|---|---|
| `startup/개요`, `빠른-시작`, `install/` | 시작하기 | 입문 핵심 재작성, 상세 설치는 선택 경로 |
| `tutorial/` 12개 주제 | 따라 만들기 | 전체 경로 수정, 첫 조회·조건 변경 추가, 소개 중복 축약 |
| `startup/handsonlab/` | 작업별 가이드 → 작업별 실습 모음 | 원본 URL·전체 예제 유지 |
| `reference/api/` | API·설정 참조 → 서버·모듈·환경설정 | 상세 설정 유지, transact 확장자 오류만 정정 |
| `startup/learning/` | API·설정 참조 → 화면 라이브러리·UI 컨트롤 | 기존 상세 API 유지, transactionAction 대표 명세 연결 |
| `reference/concept/` | 개념 이해 | 새 입구 추가, 기존 구조·설계 문서 유지 |
| `information/` | 더보기 → 커뮤니티·추가 자료 | 유지 |
| `reference/vide-coding-instruction/` | 더보기 → AI 활용 자료 | 입문 경로와 분리, 본문 전면 개작하지 않음 |
| `reference/presentation/` | 더보기 → 발표 자료 | 기존 링크 유지 |
| `twelvefactor/` | 작업별 가이드의 배포·운영 원칙 | 기존 URL·내용 유지 |
| 긴 설치 자동화 코드 | `static/install/` + 선택 설치 문서 | 원문 코드 보존, 본문에서 분리 |
| 게시판의 Copilot 설계 대화 | `information/resource/AI로-게시판-설계-검토하기` | 보조 자료로 분리, 원문 링크 유지 |

12개 옛 학습 분류 URL은 소개 문서로 연결하는 호환 페이지로 남겼습니다. 주요 옛 분류 8개와 수정 문서의 기존 절 주소도 유지했습니다. `라이선스`와 `MD-템플릿`은 기존처럼 주 메뉴 밖의 문서입니다.

## 대표 정보와 구현 확인

- `reference/거래-호출.mdx`: 실제 `syn.webform.js`의 인자, 기본 옵션, 입력·출력, 반환·오류 동작을 확인했습니다. 모든 오류가 콜백으로 전달되거나 Promise로 반환된다고 설명하지 않습니다.
- `reference/식별자와-파일-경로.mdx`: BOD 예제의 HTML/JS/JSON/XML과 실제 transact 로더를 확인했습니다. `BOD` 프로젝트와 `dbclient` 모듈을 구분하고 `.json`·`.txn`과 SQL `.xml`을 구분합니다.
- Board 초기화의 DELETE와 ID 초기화, 조회 SQL의 빈 테이블 자동 생성, DB01의 기본 연결 경로를 실제 예제 소스와 대조했습니다.
- .NET 요구사항은 `ack.csproj`의 `net10.0`, Node.js 최소 요구는 설치 스크립트를 근거로 했습니다. 실제 사용하는 배포본의 요구사항을 우선하도록 안내했습니다.
- 일반 설치 정보는 Microsoft Learn, Node.js, Git, gulp, curl, Homebrew 공식 안내로 연결했습니다. 링크 확인은 설치 동작 검증을 의미하지 않습니다.

기존 사용자 변경 6개 파일을 보존했습니다. 이 중 `transact.mdx`의 계약 경로 확장자 한 줄만 현재 로더에 맞춰 `.xml`에서 `.json`으로 정정했습니다.

## 검증

- `npm run typecheck`: 통과. 잘못된 로컬 경로 의존성을 Docusaurus 3.10.1 tsconfig로 수정하고 `--noEmit`을 명시했습니다. 기존 iframe 예제의 전역 함수 타입 오류도 최소 수정했습니다.
- `npm run build`: 통과. 깨진 내부 링크 검사 활성 상태를 유지했습니다.
- `node tests/docs-navigation.mjs`: 통과. 5개 메뉴, 학습의 다음 문서, 옛 분류 20개, 주요 절 주소와 설치 스크립트 배포 경로를 검사했습니다.
- Windows 스크립트: PowerShell 구문 검사 통과. macOS·Ubuntu 스크립트: `bash -n` 통과. 세 스크립트는 BOM·줄바꿈을 제외하면 기존 문서 코드와 동일합니다.
- `git diff --check`: 통과. 기존 문서 356개 파일의 존속과 수정 문서 30개의 이전 절 ID를 추가 점검했습니다.
- 데스크톱 브라우저(`localhost:3000`): 홈 5개 메뉴, 실행 안내 → 첫 조회 → 조건 변경 → 거래 레퍼런스, 전체 학습 경로, 화면 저작 소개와 이전 분류 주소를 확인했습니다. 새 메뉴 설정을 반영하기 위해 해당 문서 개발 서버만 재시작했습니다.
- 모바일 배포 미리보기(390×844): 메뉴 열기와 레퍼런스 이동, 표와 카드 배치를 확인했습니다. 홈 제목이 단어 중간에서 끊기거나 잘리는 문제를 작은 화면용 글자 크기로 보완하고 다시 확인했습니다. 확인한 홈·레퍼런스 페이지에 문서 전체의 가로 넘침은 없었습니다. 미리보기 콘솔 오류도 관찰되지 않았습니다.
- 임시 모바일 화면 설정은 원복했고 배포 미리보기 탭은 닫았습니다. `localhost:3000` 개발 서버와 홈은 확인 가능한 상태로 남겼습니다.

문서 빌드와 HandStack 실행은 별개입니다. 새 PC에서 전체 설치, 각 OS의 자동 설치, 실제 DB 초기화·CRUD 왕복은 실행하지 않았습니다. 따라서 예제의 End-to-End 실행 성공이나 학습 시간 개선을 주장하지 않습니다.

## 후속 평가

실제 신규 개발자에게 준비 도구 찾기 → 서버 실행 → 첫 조회 → 제목 검색 안내 수정 → 오류 원인 찾기를 요청합니다. 단계별 성공 여부, 막힌 문장·링크, 도움 요청 횟수, 설치 다운로드를 분리한 작업 시간을 기록하세요. 유지보수 개발자에게는 transactionAction 옵션과 DB01 연결 위치 찾기를 요청합니다.

전후 비교 결과로 다음 우선순위를 정합니다. 아직 재검증하지 않은 저장·팝업·확장 모듈 본문은 같은 기준으로 이어서 점검하고, 긴 문서라는 이유만으로 고유 명세를 삭제하지 않습니다.
